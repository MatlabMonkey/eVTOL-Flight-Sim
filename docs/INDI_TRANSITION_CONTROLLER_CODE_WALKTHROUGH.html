INDI Transition Controller Code Walkthrough

Last reviewed: 2026-04-27 00:00 PDT. This document mirrors the first implementation of the scheduled longitudinal INDI controller.

Controller Stack

The implementation is split into an offline builder and a runtime controller. The builder can be rerun as the trim sweep database grows. The runtime file is kept codegen-friendly for the MATLAB Function dispatch block.

controllers/builders/build_indi_transition_controller.m
  -> load trim DB and INDI effectiveness map
  -> select a smooth path through candidate trim points
  -> pack x_ref, trim_cmd, and G schedules into controllerData

controllers/controller_indi_transition.m
  -> gated path scheduler
  -> outer-loop specific-force and pitch-acceleration command
  -> INDI weighted least-squares allocator
  -> actuator command limiting

controllers/controller_dispatch.m
  -> controller_id = 6 calls controller_indi_transition

Builder File

build_indi_transition_controller(opts) owns all non-codegen work. It reads the current trim database and the INDI surface-effectiveness database, then writes a compact numeric schedule into controllerData.

Top-Level Builder

opts = localApplyDefaults(opts);
evalin('base', 'Init_Main');

trimTable = localLoadTrimCandidateTable(opts.trim_db_file);
indiMaps = localLoadIndiMaps(opts.indi_map_file);
plant = localLoadPlantDataFromBase();

[pathTable, pathDebug] = localSelectPath(trimTable, opts.path);

for each path point
    stateSchedule(:,i) = state + path metadata
    trimSchedule(:,i) = nominal trim actuators
    indiSchedule(:,:,i) = G + allocator weights
end

Math

Each path point stores a local linearized input-to-virtual-output map:

\[ \Delta \nu \approx G_i \Delta \eta, \qquad G_i = \left. \frac{\partial [f_x,f_z,\dot q]^T} {\partial [\Omega_f^2,\Omega_r^2,\delta_f,\delta_e]^T} \right|_{i} \]

Path Selection

localSelectPath filters out unusable trim rows, builds candidate sets around a guide curve in \(V_\infty\)-tilt space, and uses dynamic programming to minimize total point and edge cost. The first and last guide points are forced to the nearest valid candidates so hover and cruise anchors do not get skipped.

\[ J = \sum_i J_{\text{point}}(i) + \sum_i J_{\text{edge}}(i,i+1) \] \[ J_{\text{edge}} = \Delta V^2 + \Delta \theta_{\text{tilt}}^2 + w_u \left(\Delta \Omega_f^2+\Delta \Omega_r^2+\Delta \delta_f^2+\Delta \delta_e^2\right) + w_\alpha \Delta\alpha^2 + w_\theta \Delta\theta^2 \]

Propeller Effectiveness

localPropColumn computes propeller columns analytically from the thrust constant and rotor locations. Front prop direction changes with scheduled front tilt; rear prop direction is fixed vertical in this first controller.

\[ T = k_T \Omega^2, \qquad \frac{\partial F}{\partial \Omega^2} = k_T \hat d, \qquad \frac{\partial M}{\partial \Omega^2} = r \times k_T \hat d \] \[ G_{\text{prop}} = \begin{bmatrix} \frac{1}{m}\frac{\partial F_x}{\partial \Omega^2} \\ \frac{1}{m}\frac{\partial F_z}{\partial \Omega^2} \\ \frac{1}{I_{yy}}\frac{\partial M_y}{\partial \Omega^2} \end{bmatrix} \]

Surface Effectiveness

localNearestSurfaceDerivative samples the prebuilt map over \(V_\infty,\alpha,\delta\). The map stores force and moment derivatives for flaps and elevator from the trim plant / polar-derived sampling workflow.

\[ G_{\delta} = \begin{bmatrix} \frac{1}{m}\frac{\partial F_x}{\partial \delta} \\ \frac{1}{m}\frac{\partial F_z}{\partial \delta} \\ \frac{1}{I_{yy}}\frac{\partial M_y}{\partial \delta} \end{bmatrix}_{(V_\infty,\alpha,\delta)} \]

Runtime File

controller_indi_transition is the code that actually runs in Simulink through controller_dispatch. It is intentionally numeric and explicit so it can compile in a MATLAB Function block.

Schedule Inference

nPts = localInferScheduleCount(x_ref_schedule, trim_cmd_schedule);
tilt_sched = localScheduleRow(x_ref_schedule, 10, nPts);
vinf_sched = localScheduleRow(x_ref_schedule, 11, nPts);
progress_sched = localScheduleRow(x_ref_schedule, 12, nPts);

The schedules are padded to fixed Simulink sizes, so the runtime controller infers the real path length from the monotonic progress row.

Gated Scheduler

localAdvanceScheduler holds the current waypoint until the measured state settles, then ramps to the next point over segment_ramp_time_s. This replaces the earlier blind time-only scheduler.

\[ \text{settled} = |\theta-\theta_i| \le \epsilon_\theta \land |u-u_i| \le \epsilon_u \land |w-w_i| \le \epsilon_w \land |q-q_i| \le \epsilon_q \] \[ \lambda_{k+1} = \min\left(\lambda_k + \frac{\Delta t}{T_{\text{ramp}}}, 1\right) \]

Specific-Force Command

The accelerometer channel is treated as body specific force. At steady non-accelerating trim, the target specific force is not zero; it is gravity projected into body axes. That is why pitch appears in the acceleration feedforward.

\[ \nu_{\text{ff}} = \begin{bmatrix} g\sin\theta^\star \\ -g\cos\theta^\star \\ 0 \end{bmatrix} \] \[ \nu_{\text{cmd}} = \begin{bmatrix} g\sin\theta^\star + k_u(u^\star-u) \\ -g\cos\theta^\star + k_w(w^\star-w) \\ k_q(q^\star-q) + k_\theta(\theta^\star-\theta) \end{bmatrix} \]

INDI Increment

The measured acceleration estimates the nonlinear drift plus the effect of the current actuator state. The controller only solves for the incremental change required to move from measured acceleration to commanded acceleration.

\[ \Delta \nu = \nu_{\text{cmd}} - \nu_{\text{meas}} \approx G(x,\eta_{\text{actual}})\Delta \eta \] \[ \Delta\eta = \arg\min_{\Delta\eta} \left\|W_\nu(G\Delta\eta-\Delta\nu)\right\|_2^2 + \left\|W_\eta\Delta\eta\right\|_2^2 \] \[ \Delta\eta = (G^T W_\nu^2 G + W_\eta^2)^{-1} G^T W_\nu^2 \Delta\nu \]

Actual Actuator State

localMeasuredEta uses actual actuator states, not commanded states, to avoid mapping the INDI increment around the wrong point when the actuators lag.

front_rpm = mean([rpm_FR, rpm_FL]);
rear_rpm  = mean([rpm_RR, rpm_RL]);
delta_f   = mean([delta_LW, delta_RW]);
delta_e   = mean([delta_LT, delta_RT]);

eta_base = [front_rpm^2; rear_rpm^2; delta_f; delta_e];

Command Reconstruction

localEtaToMixedCommand converts the INDI variables back to the mixed actuator command convention used by dispatch. Aileron and rudder are intentionally zero for this longitudinal controller.

\[ \eta_{\text{cmd}} = \eta_{\text{actual}} + \Delta\eta \] \[ \Omega_{f,\text{cmd}} = \sqrt{\max(\Omega_{f,\text{cmd}}^2,0)}, \qquad \Omega_{r,\text{cmd}} = \sqrt{\max(\Omega_{r,\text{cmd}}^2,0)} \]

How To Use

Init_Main
addpath('controllers')
addpath('controllers/builders')

controllerData = build_indi_transition_controller();

% Then prepare a run in the usual workflow:
% trimResult should describe the starting hover/low-speed point.
runCase = struct('useController', true, 'attemptSimulation', true, 'stopTime_s', 240);
Run_Main

The trim sweep database is still allowed to improve. Rerunning build_indi_transition_controller should automatically pick from the newer trim candidates as long as the database schema stays compatible.

1. What This Folder Is For

This folder is the working simulation workflow for our eVTOL project. The main idea is: 

Init_Main
trimCase = ...
Trim_Main
Build_Controller_EVTOL_Cruise   % optional / only if trim succeeded
runCase = ...
Run_Main

Scripts pass structured data like initData, trimResult, and runCase. The Simulink models still use plain workspace variables and From Workspace inputs.

3. Quick Start

Hover trim that currently works

cd('.../eVTOL-Flight-Sim/eVTOL_Simulation')
Init_Main
trimCase = TrimCase_Hover();
Trim_Main

Open-loop wrapper prep only

Init_Main
trimCase = TrimCase_Hover();
Trim_Main
runCase = RunCase_PrepOnly();
Run_Main

Attempt a wrapper simulation

Init_Main
trimCase = TrimCase_Hover();
Trim_Main
runCase = RunCase_OpenLoopMainAttempt();
Run_Main

After Run_Main, the main script leaves runSpec, runContext, runResult, and simOut in the workspace.

4. Initialization

Init_Main just calls Full_Sim_Init.m. This sets up:

  • aircraft constants from aircraft_def.m
  • active model names (Trim_Plant and Wrapper)
  • default timing and initial conditions
  • default grouped motor and tilt commands
  • workspace variables that existing Simulink blocks still expect

If you start from a clean MATLAB workspace, run Init_Main first.

5. How Trim Works Right Now

The main trim entrypoint is Trim_Main, which calls trim_evtol_case(initData, trimCase, options).

A trim case is just a MATLAB function that returns a struct. The most important fields are:

Operating-point fields

  • name, mode
  • Vinf_mps
  • u_body_mps, v_body_mps, w_body_mps
  • phi_deg, psi_deg, theta_guess_deg
  • front_tilt_deg

Trim-logic fields

  • body_velocity_known, body_velocity_steady
  • euler_known, euler_steady
  • mixed_control_known
  • use_vinf_output_constraint
  • use_vertical_speed_output_constraint

Seeds / guesses

  • front_collective_guess_rpm
  • rear_collective_guess_rpm
  • delta_f_guess_deg
  • delta_e_guess_deg

Validation fields

  • trim_validation_stop_time_s
  • validate_nonlinear_hold
  • surface_limit_deg
  • surface_rate_limit_deg_s

The trim plant now takes both direct surface inputs and mixed controls. The current trim formulation fixes the direct physical surface inputs at zero and trims using the mixed channels delta_f, delta_a, delta_e, and delta_r.

6. Current Trim Status

These were rechecked in the current folder state. “Works” here means trimResult.success = true and the trim termination string says the operating-point specifications were successfully met.

Trim case Status Notes
TrimCase_Hover() Working Current default hover case trims cleanly. Uses the geometry-based front/rear collective seed: about 1865.7 rpm front and 1756.4 rpm rear, with mixed controls fixed at zero.
TrimCase_Cruise75() Not exact-working Current case only frees front collective, rear collective, and delta_e. It does not satisfy all trim constraints at exact 75 m/s in the current folder state.
TrimCase_Cruise75_FlapElevator() Working Current known-good 75 m/s cruise trim. Uses the mixed-control path with delta_f and delta_e free, while delta_a and delta_r stay fixed at zero. A representative exact trim is about front collective = 808.9 rpm, delta_f = +0.794 deg, and delta_e = -4.353 deg.
TrimCase_Cruise75_FlapElevator() with rear collective fixed Working family This trim also works as a small 1-parameter cruise family when the rear collective is held at different fixed values. Verified exact trims so far: rear = 0 rpm, rear = 200 rpm, and rear = 500 rpm. The front collective and the symmetric flap/elevator trim rebalance around that rear-collective schedule.
TrimCase_Cruise75_Longitudinal() Not exact-working Longitudinal-only cruise attempt with front collective, rear collective, delta_f, and delta_e free. Still does not satisfy the current exact trim constraints.
TrimCase_Cruise75_CollectiveElevator() Not exact-working Front collective, rear collective, and delta_e only. Useful as an exploratory case, but not an exact 75 m/s trim in the current folder.
TrimCase_Cruise75_PropOnly() Not exact-working Prop-only cruise trim. As expected, this is not enough for exact cruise in the current model.

Short version: hover is restored and reliable, and exact 75 m/s cruise trim is restored through the TrimCase_Cruise75_FlapElevator() family. The older experimental cruise cases are still useful for exploration, but they are no longer the best “known-good” cruise entrypoints.

7. How To Make Or Edit A Trim Case

Put trim cases in cases/trim. The intended pattern is one small function per case. 

function trimCase = TrimCase_MyNewCase()
trimCase = TrimCase_Hover();   % or TrimCase_Cruise75(), if that is a better starting point
trimCase.name = 'MyNewCase';
trimCase.Vinf_mps = 60.0;
trimCase.front_tilt_deg = 90.0;
trimCase.front_collective_guess_rpm = 900.0;
trimCase.rear_collective_guess_rpm = 250.0;
trimCase.mixed_control_known = [true; true; false; true];
trimCase.delta_e_guess_deg = -5.0;
end

The simplest workflow is usually to copy a nearby case and change only a few fields.

8. Controller Build

Build_Controller_EVTOL_Cruise calls Design_LQR_Controller_EVTOL_Cruise.m.

The current controller build expects:

  • a successful trimResult
  • a 9-state rigid-body linear model from the trim step
  • mixed-control input ordering: [front_collective, delta_f, delta_a, delta_e, delta_r]

At the moment, this is best thought of as a cruise LQR path that depends on cruise trim being exact. The current best starting point for exact cruise work is TrimCase_Cruise75_FlapElevator(). The older experimental cruise cases are still useful for diagnostics, but they should not be the default controller-build seed. 

Init_Main
trimCase = TrimCase_Cruise75_FlapElevator();
Trim_Main
Build_Controller_EVTOL_Cruise

9. Running The Wrapper

Run_Main takes the current trimResult and optional controllerData, builds command traces, publishes wrapper-facing workspace variables, and then optionally simulates Wrapper.

Current run cases

Run case What it does
RunCase_PrepOnly() Builds all wrapper inputs but does not actually simulate.
RunCase_OpenLoopMainAttempt() Attempts an open-loop wrapper simulation.

Typical wrapper run

Init_Main
trimCase = TrimCase_Hover();
Trim_Main
runCase = RunCase_OpenLoopMainAttempt();
Run_Main

Suite run

Init_Main
trimCase = TrimCase_Hover();
Trim_Main
Run_EVTOL_Suite

By default, Run_EVTOL_Suite runs:

  • RunCase_PrepOnly()
  • RunCase_OpenLoopMainAttempt()

10. Plotting Wrapper Outputs

The plotting helper is plot_evtol_workspace_outputs.m. It expects the wrapper simulation output to be in a base-workspace variable named out.

Important: Run_Main currently leaves the simulation output in simOut, not out. So after a run, do this first: 

out = simOut;

Then you can plot:

plot_evtol_workspace_outputs
plot_evtol_workspace_outputs('important')
plot_evtol_workspace_outputs('all')

The helper also plots cmds when you use the broader modes.

11. Making A Video

Use make_evtol_video.m after a wrapper run. The easiest case is to pass the simulation output directly: 

make_evtol_video('sim_out', simOut)

Or, if you want to use the default workspace variable names: 

out = simOut;
make_evtol_video('sim_out_var', 'out')

The helper looks for:

  • truth signals like pos_NED, eul_truth, V_B_truth, omega_truth
  • internal logging like viz_tilt_states, viz_surface_states, viz_prop_rpm

By default, videos go into workspace_plots/. Existing examples in that folder include:

  • lqr_120s_airspeed_step30_10s.mp4
  • lqr_120s_roll_step30_10s.mp4
  • out_video_test.mp4
  • quick_video_test2.mp4

12. Batch Trim Sweeps

If you want to scan a small trim grid, use: 

Init_Main
trimSweep = TrimSweep_CruiseGrid();
Trim_EVTOL_Sweep

TrimSweep_CruiseGrid() currently sweeps:

  • Vinf_mps = 70:5:80
  • front_tilt_deg = 90

14. Recommended Teammate Workflow Right Now

  1. Run Init_Main.
  2. Use TrimCase_Hover() if you need a known-good trim today.
  3. Use TrimCase_Cruise75_FlapElevator() if you need a known-good exact 75 m/s cruise trim today.
  4. Use Trim_Main to solve the trim.
  5. Use RunCase_PrepOnly() first if you are just checking the workspace handoff into the wrapper.
  6. Use RunCase_OpenLoopMainAttempt() when you actually want to try the wrapper.
  7. After a run, do out = simOut; before using the plotting helper.

If you are doing cruise work, start from the flap/elevator cruise family and only switch back to the older experimental trim cases when you are intentionally debugging trim authority or formulation choices.
